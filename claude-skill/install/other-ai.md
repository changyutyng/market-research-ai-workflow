# 市場研究 AI 協作流程

> 用 AI 做出**可查證、可被推翻**的桌面研究報告。
> 整理自一次真實專案：14 個研究對象 × 30 個欄位、13 條假設、98 筆逐條來源、48 頁結論文件，約三個工作天完成。

---

## 先讀這段：這份文件不能整份交給 AI 執行

這套流程有四個地方必須由人來做：

1. **階段 1** 要貼進團隊內部真實的爭論，AI 沒有那個資訊
2. **階段 3** 的欄位要由你確認是否對應得上你的假設
3. **階段 4** 產出的每個網址要由你點開驗證
4. **階段 7** 的「這句我看不懂」，只有讀的人能發現

把整份貼進去說「照這個做」，AI 會一口氣把七階段都「做完」，給你一份完整漂亮、但沒有一處被驗證過的報告 —— 正好是這套流程要避免的結果。

**正確用法：** 把下面〈專案指示〉貼進 ChatGPT 的 Projects 專案指示欄（或 Claude 的 Project 自訂指示）。然後一次貼一個階段的指令，每個階段做完自己檢查，再進下一個。

---

## 專案指示（貼進專案設定，全程生效）

```
你在協助我做一份市場研究。這份研究要能被查證，也要能被推翻。

以下規則在整個專案的每一次回答都適用：

【來源】
1. 收費、規章、票價、日期這類數字，只採用官方簡章、官網或官方新聞稿。
   二手整理的文章不算數。
2. 主辦方或公司自己宣稱的成果（人次、成交率、市占、滿意度），
   一律標註「業者自述」，並註明未經第三方查核。
3. 每一條事實都要附網址與取得日期。
4. 查不到就寫「查無」，並列出你查過哪些地方。
   不要用推測、不要用「一般而言」把空格填滿。
5. 我會點開你給的每一個網址驗證。
   給不出可驗證網址的內容，一律寫查無，不要生成看起來合理的網址。

【判定】
凡是對假設下結論，只能三選一：
  已驗證 —— 有先例，且結果支持假設
  資料不足 —— 無直接先例，或證據相關但無法建立因果
  推翻 —— 有先例，且結果與假設相反
「大概可以」「應該沒問題」「值得樂觀」一律歸到資料不足。

【寫法】
・先講結論，再講依據
・屬於推論而非資料直接支持的，句首標「推論」
・不要用「總體而言」「值得注意的是」「綜上所述」這類沒有資訊的句子
・避免行話。需要圈內知識才看得懂的詞，換掉
・專有名詞第一次出現要解釋

【你不要做的事】
・不要為了讓段落完整而補沒查證的內容
・不要把兩個統計基準不同的數字放在一起比較
・不要把「我查不到」寫成「不存在」或「沒有先例」
```

## 階段 1　把質疑變成假設

**為什麼先做這個：** 沒有假設的研究會變成資料堆積。你會知道很多事，但做不了任何決定。

```
我要做一份市場研究，但先不要開始查資料。

第一步只做一件事：把下面這段描述裡，所有「我們相信但還沒驗證」的事情，
逐條列成可檢驗的假設。

要求：
1. 每條假設要能被「有先例／沒先例」判定，不要寫成價值判斷
2. 每條後面寫明：要驗證它，需要看到什麼樣的證據才算數
3. 如果某個信念根本無法用桌面研究驗證，直接說明，不要勉強列進去

［貼上你的商業模式描述、團隊內部的爭論、你自己最不確定的地方］
```

**產出：** 編號的假設清單。這份清單會變成研究的骨架，也會變成報告裡的一章。

**你要檢查：** 每條假設是不是真的「可判定」？如果一條假設你想不出什麼證據能推翻它，那它是信仰不是假設，刪除。

---

## 階段 2　定義對象，而且判準只能有一個

**為什麼：**「相似的公司」是模糊詞。判準不明確，後面所有比較都會各說各話。

```
依據上面的假設清單，列出需要研究的對象。

分類判準必須先講明白，而且只能用一個判準。
不要用「相似度」「相關性」這種可以各自解讀的詞。

每個對象要標明：
・它屬於哪一類，為什麼
・它能幫我們驗證哪幾條假設
・它的資料公開程度如何

如果有對象你認為該納入但我沒提到，列出來並說明理由。
資料完全不公開的對象，建議排除並說明原因。
```

**產出：** 對象清單＋判準一句話。那句判準後來會原封不動寫進報告的研究範圍。

---

## 階段 3　先定欄位，再查資料

**為什麼：** 欄位就是研究設計。先查再整理，會得到一堆無法橫向比較的散文。

```
在開始查資料之前，先設計這份研究的欄位。

規則：
1. 每一欄都要能讓所有對象橫向比較
2. 每一欄都要對應到至少一條假設。不對應任何假設的欄位不要放
3. 欄位要問「事實」不要問「評價」
   （問「費用多少」，不要問「費用是否合理」）
4. 每一欄都要事先想好：如果查不到，要怎麼標示

列出一張表：欄位名稱｜這欄要回答什麼｜資料可能在哪裡｜查無時怎麼寫
```

**你要檢查：** 把欄位表和假設清單並排看，有沒有哪條假設沒有任何欄位在支撐它？有的話補欄位。

---

## 階段 4　查證（要分批，不要一次全部交給它）

**為什麼要分批：** 上下文太長時，AI 會開始放寬來源標準。每批重貼一次來源規則。

```
以下是研究對象清單與欄位表。這一批請查證這幾個對象：［列出 3 到 5 個］

來源規則，每一條都要遵守：
1. 數字只採用官方簡章、官網或官方新聞稿，二手文章不算
2. 業者自述的成果一律標註「業者自述」
3. 每條事實附網址與取得日期
4. 查不到就寫「查無」，並列出你查過哪些地方
5. 我會點開你給的每一個網址驗證。
   給不出可驗證網址的內容，一律寫查無

產出：每個對象一節，依欄位表逐欄填寫，查無的欄位保留並標示。
```

**你要檢查（這一步最重要）：** 隨機抽 5 到 10 個網址點開。如果錯誤率超過兩成，整批重做，並在下一批的指令開頭加一句：「上一批有 N 個網址無法驗證，這批請降低產出量、提高可驗證性。」

> **真實案例：** 我們另外請一個 AI 做交叉查證，它給的 8 個引用網址裡有 5 個是錯的 —— 指向不相干文章、連到無關公司、或 404。文字結論大致合理，但出處是捏造的。
> 原因是它用的搜尋工具只回摘要、不回網址，被要求附來源時就自己生成了看起來合理的網址。
> **AI 給的網址預設當成假的。**

---

## 階段 5　事實進試算表，不要直接寫文件

**為什麼：** 把「事實層」和「論述層」分開。同一個數字只存在一個地方，改一次就全對。

```
把查證結果整理成三個分頁的資料表，以 CSV 格式產出，一個分頁一段。

分頁一　對照表：對象為欄、欄位為列，每格填查證結果，查無就寫查無

分頁二　假設判定：每條假設一列，欄位為
　　編號｜假設｜證據摘要｜判定｜意涵｜出處
　　判定只能三選一：已驗證／資料不足／推翻

分頁三　來源：對象｜來源名稱｜網址｜取得日期｜這筆資料用在哪一欄或哪一章
```

**產出：** 貼進 Google Sheet 或 Excel。就算報告沒寫完，這張表本身已經可以交付。

> **為什麼判定要分三級：** 只分「成立／不成立」會逼人把「還不知道」講成「大概成立」。
> 分出「資料不足」這一級，等於允許研究誠實地說不知道 —— 而不知道本身就是決策資訊，它告訴你哪些事必須靠實測。
> 我們最後 13 條假設裡有 8 條是資料不足，那 8 條後來變成首屆活動必須現場量測的指標。

---

## 階段 6　依據資料表撰寫文件

```
依據資料表寫成報告。

內容規則
・所有數字必須回得到來源分頁的某一列。表上沒有的數字不要出現
・屬於推論而非資料直接支持的，句首標「推論」
・每一章結尾要有一段「對我們的意涵」，
　寫明這章的發現會改變哪個決定，不要只摘要前面講過的話
・查無的事情要寫出來，並說明查過哪些地方

結構
每章固定三段：這個對象是什麼 → 跟我們哪裡相同哪裡不同 → 對我們的意涵

最後加一章「假設驗證」，把分頁二整理成表，並說明三種判定的定義。
```

## 階段 7　逐段審查（這一階段沒有 prompt）

**不要一次讀完才給整體意見。** 逐段讀，遇到任何一句看不懂，就把那句貼回去問：

> **「這句是什麼意思？」**

這句話的威力比任何 prompt 技巧都大。AI 寫出你看不懂的句子，九成不是因為你不懂，是因為它沒想清楚，用一個抽象的詞把空缺蓋過去了。

審查時交替使用的三句話：

- 這句是什麼意思？
- 這個結論的證據是什麼？
- 這是查到的，還是你推論的？

> **真實案例：** 我們被指出的詞包括「收縮」（誰在收縮、收縮什麼）、「行情」（指市場普遍條件，但三個抽象詞連用就讀不懂）、「兩者」（前一段提了三組東西，不知道指哪兩個）。
> 每一個被問出來的地方，改寫後都變成更具體、也更有用的內容。

## 補充階段　當結論是「查不到」的時候

「我查不到」跟「它不存在」是兩件事。報告裡只要出現「查無」「不存在」「沒有先例」，都值得換管道再查一次。

```
以下這個結論目前的證據是「查不到」。
「查不到」不等於「不存在」，可能只是管道不對。

請換一批管道再查一次。搜尋引擎查不到的東西，
通常在這些地方：論壇的分板與站內搜尋、部落格平台的標籤頁、
社群平台的站內搜尋、產業公會或主管機關的公開文件。

每找到一條：
・附上原文逐字，不要改寫、不要摘要
・附上網址
・說明你用什麼方式確認這段話確實出現在那個頁面上
・標明發言者的身分，以及你怎麼確認的

找不到也要回報你查了哪些管道、各自的結果數。
```

> **真實案例：** 第一輪查不到任何一般消費者討論這個價格帶的產品，初稿寫的是「公開討論中為語彙真空」。
> 換管道再查之後找到 32 條逐字發言，結論從「查無」變成正面證據，那一章從全份報告最弱的一節變成最強的一節。

## 五條不能違反的規則

| | 規則 | 原因 |
|---|---|---|
| 1 | **先有假設，再有研究** | 沒有假設的研究會變成資料堆積 |
| 2 | **先定欄位，再查資料** | 欄位就是研究設計 |
| 3 | **事實放表，論述放文件** | 同一個數字只存在一個地方 |
| 4 | **判定分三級，不要只分對錯** | 允許研究說「不知道」 |
| 5 | **AI 給的網址預設是假的** | 沒有例外，也沒有捷徑 |

## 其他實際發生過的錯誤

**數字誤讀。** 報告寫某個對象「從 468 降到 46」，讀起來很驚人。再查一次發現 46 只是某個分區的數字，不是全場。正確序列是 468 → 339 → 數十，趨勢是真的，但原本的對比是錯的。
→ 凡是「從 A 降到 B」的句子，都要分別確認 A 和 B 的統計基準是否一致。

**引文沒驗身分。** 第一版引用了一批「業內人士的抱怨」，看起來很有說服力。實際檢查發現那些發言來自完全不同行業的人。整節重查後改成 19 條來自 10 位具名從業者的逐字發言，每條都開頁面確認過。
→ 引文的說服力完全建立在發言者身分上。身分沒驗證，引文就是裝飾。

**整段替換時的內容遺失。** 改寫時若用「找到這段、換成那段」操作，而比對的關鍵字只對到段落前半，後半會被整段覆蓋。
→ 每次大幅改寫後，用改寫前的版本做一次逐行比對。

## 對 ChatGPT 使用者的幾個實務提醒

- **用 Projects 功能。** 把〈專案指示〉放進專案說明欄，規則才會在每次對話持續生效。放在單次對話裡，聊久了會失效。
- **每個階段開新對話。** 上下文太長時，它會開始忘記來源規則、放寬標準。
- **階段 4 一定要分批。** 一次查 3 到 5 個對象，每批重貼來源規則。
- **把產出存成檔案。** 每階段結束把結果存成 md 或 csv，下個階段用附檔方式提供給它，比讓它「記得」可靠得多。
- **確認它真的在上網。** 如果它沒有開啟搜尋就回答，給的全部是訓練資料裡的舊資訊，而且不會主動告訴你。每一批開頭可以要求它先列出「我接下來要查的網站」。

---

*這份流程適用於需要可查證、可被推翻的桌面研究。如果只需要快速概覽，一個 prompt 就夠了。*
