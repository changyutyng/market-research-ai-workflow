# 市場研究：從質疑到報告

這個 skill 的價值不在「幫你查得快」，在**強制你停下來檢查**。
沒有檢查點的市場研究，產出的東西會看起來很完整，但不能拿去做決定。

---

## 強制規則：一次只做一個階段，做完必須停

**絕對不可以一口氣跑完七個階段。** 每個階段結束，回報產出、列出使用者要檢查的事項，然後停下來等回覆。

使用者說「全部做完」「不用停」時，仍然要停在第 1、3、4、7 這四個階段 —— 這四個的檢查只有人能做：

| 階段 | 為什麼只有人能做 |
|---|---|
| 1 假設 | 要貼進團隊內部真實的爭論，我沒有那個資訊 |
| 3 欄位 | 要確認欄位對不對得上使用者真正在意的決定 |
| 4 查證 | 網址要實際點開驗證（可用 `scripts/verify_urls.py` 協助，但判斷由人做） |
| 7 審查 | 「這句我看不懂」只有讀的人能發現 |

階段 2、5、6 若使用者明確說「直接做下去」，可以連著做。

---

## 開場：先確認在哪一階段

被叫起來時，第一件事是判斷狀況，**不要直接開始查資料**。

- 全新題目 → 從階段 1 開始
- 使用者已有假設或對象清單 → 問清楚現況，從對應階段接手
- 使用者提供一份已完成的研究要改 → 多半是階段 7，直接進審查模式

確認後用一句話說明「我們現在在第幾階段、這一階段要產出什麼、做完你要檢查什麼」，再開始。

---

## 七個階段

### 1　把質疑變成假設

不要從「研究這個市場」開始，要從「我們相信什麼、憑什麼」開始。

請使用者提供：商業模式描述、團隊內部的爭論、他自己最不確定的地方。

產出一份編號的假設清單，每條要：
- 能被「有先例／沒先例」判定，不是價值判斷
- 附上「要驗證它需要看到什麼證據才算數」
- 無法用桌面研究驗證的，直接說明，不要勉強列進去

**停下來，請使用者檢查：** 每條假設想不想得出什麼證據能推翻它？想不出來的那條是信仰不是假設，刪除。

### 2　定義對象，判準只能有一個

分類判準必須先講明白，而且只能用一個。不要用「相似度」「相關性」這種可以各自解讀的詞。

每個對象標明：屬於哪一類及理由、能驗證哪幾條假設、資料公開程度。
資料完全不公開的對象，建議排除並說明原因。

判準那一句話之後會原封不動寫進報告的研究範圍章節。

### 3　先定欄位，再查資料

欄位就是研究設計。先查再整理，會得到一堆無法橫向比較的散文。

欄位規則見 `references/field-design.md`。核心四條：
1. 每一欄要能讓所有對象橫向比較
2. 每一欄要對應至少一條假設，不對應的不要放
3. 問事實不問評價
4. 事先想好查不到要怎麼標示

**停下來，請使用者檢查：** 把欄位表和假設清單並排，有沒有哪條假設沒有欄位在支撐？

### 4　查證（分批，不要一次全部交給它）

完整來源規則見 `references/source-rules.md`，整個階段每一批都要重申。

- 有 subagent 可用時，分組平行查，每組 3 到 5 個對象
- 沒有時分批跑，**每批重貼一次來源規則**（不重貼，跑到後面標準會放寬）
- 每個對象一節，依欄位表逐欄填寫，查無的欄位保留並標示

查完**必須**跑網址驗證：

```bash
python3 scripts/verify_urls.py <查證筆記檔案> --sample 0   # 全部驗
```

錯誤率超過兩成就整批重做，下一批指令開頭加一句「上一批有 N 個網址無法驗證，這批請降低產出量、提高可驗證性」。

**停下來，把驗證結果給使用者看。**

### 5　事實進表，不要直接寫文件

把事實層和論述層分開。同一個數字只存在一個地方，改一次就全對。

三個分頁，欄位定義見 `references/templates.md`：
- **對照表**：對象為欄、欄位為列
- **假設判定**：編號｜假設｜證據摘要｜判定｜意涵｜出處
- **來源**：對象｜來源名稱｜網址｜取得日期｜用在哪一欄或哪一章

判定只能三選一：**已驗證／資料不足／推翻**。
「大概可以」「應該沒問題」一律歸到資料不足。三級的完整定義見 `references/source-rules.md`。

有 Google Workspace 工具可用時直接建表；沒有就輸出 CSV 讓使用者自己貼。

### 6　依據資料表撰寫文件

依據資料表寫，不是依據原始筆記。這樣可以避免寫作時「順手」補進沒查證的內容。

內容規則：
- 所有數字必須回得到來源分頁的某一列，表上沒有的數字不要出現
- 推論而非資料直接支持的，句首標「推論」
- 每章結尾一段「對我們的意涵」，寫明會改變哪個決定，不要只摘要前面
- 查無的事要寫出來，並說明查過哪些地方

寫法規則：先講結論再講依據；不用「總體而言」「值得注意的是」這類沒有資訊的句子；避免行話。

每章固定三段：**這個對象是什麼 → 跟我們哪裡相同哪裡不同 → 對我們的意涵**。

### 7　逐段審查

**這一階段沒有自動化。** 請使用者逐段讀，看不懂就把那句貼回來。

使用者丟一句話回來時，不要只是換句話說。先判斷是哪一種問題：

| 症狀 | 多半是 |
|---|---|
| 抽象名詞沒有主詞（「收縮」「成長」） | 寫的時候沒想清楚是誰、在哪個維度 |
| 行話（「行情」「賽道」「打法」） | 需要圈內知識才看得懂，要換成白話 |
| 代名詞指涉不明（「兩者」「前者」） | 前文提了三個以上的東西 |
| 一句話放進三個抽象概念 | 要拆成三句 |

改寫時**先講清楚那個詞指的是什麼**，再重組句子。不要只是換同義詞。

## 補充階段：當結論是「查不到」

「我查不到」跟「它不存在」是兩件事。報告裡只要出現「查無」「不存在」「沒有先例」，都要換管道再查一次。

搜尋引擎查不到的，通常在：論壇的分板與站內搜尋、部落格平台的標籤頁、社群平台站內搜尋、產業公會或主管機關的公開文件。

每找到一條要附：原文逐字（不改寫不摘要）、網址、確認方式、發言者身分與如何確認。
找不到也要回報查了哪些管道、各自結果數。

## 全程適用的鐵則

1. **AI 給的網址預設是假的。** 每一條都要驗。沒有例外。
2. **引文要驗身分。** 說服力完全建立在發言者身分上，身分沒驗證，引文就是裝飾。
3. **不要把兩個統計基準不同的數字放在一起比。** 凡是「從 A 降到 B」，分別確認 A 和 B 的定義。
4. **不要把「我查不到」寫成「不存在」。**
5. **大幅改寫後要逐行比對。** 整段替換時，比對字串只對到前半會讓後半被覆蓋掉。

常見失敗模式與真實案例見 `references/failure-modes.md`。

## 邊界

這套流程適用於需要可查證、可被推翻的桌面研究。
只需要快速概覽、或只查一個事實時，不要套用，直接查就好 —— 七個階段的成本在那種情境下不划算。
